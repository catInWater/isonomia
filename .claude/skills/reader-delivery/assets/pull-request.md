# PR 正文模板

填写下列小节，去掉占位说明。保持当前会话要求的归属尾注。

## 变更与范围

- <用户可感知的变化、缺陷根因或工程目的；指出不在范围内的项。>
- 依据：<规格、票据、ADR 链接>。

## 验证

- <完整验证报告链接，指向已推送的证据文件。>
- <关键复现步骤、实际运行命令、结果和仍未验证项。>

## GUI 测试截图

在正文内直接嵌入带说明的关键截图。已提交的图片可用以下 URL 结构，替换为**实际已推送且含该图片的证据提交 SHA**。不要用当前未提交的 SHA 占位当作成品链接。

```md
![操作后的界面状态](https://github.com/OWNER/REPO/blob/EVIDENCE_SHA/.claude/docs/validation/assets/TOPIC/STATE.png?raw=true)
```

无法实测说明阻塞；与界面无关写「不适用」并说明理由，不贴旧图充数。

## 远端检查与人工审查

- <待运行，或最新 head SHA、Linux/Windows/其他必需检查的当前状态与运行链接。>
- <PR 正文评论、review 与行内线程的检查时点；列出已处理意见及证据、待用户裁定的歧义/冲突/超范围意见，不代表用户解决线程。>
- <建议人工核对的项目和限制。每次 review 修订推送后重新检查新 SHA 的 CI；最终仍由用户审查并合并。>
