# ADR-0004 连续笔记、引用与保存会话

- 状态：阶段 4 工程实现；平台和 GUI 验证边界见[验证报告](../validation/04-notes.md)
- 关联：[S04](../specs/04-notes.md)、T-018～T-020、[D-03/D-06/D-07](../specs/README.md)、[出处锚点](0003-source-anchors.md)

## 文档与编辑器

每书沿用稳定记录 `note-<bookId>`，不另建多笔记集合。文档为 JSON 字符串：`{schemaVersion:1,html,sources,importedAnnotationIds}`。HTML 只表达段落、二级标题、有序/无序列表、引用和加粗；来源保存在独立的 `SourceAnchor` 数组，不把链接、DOM 位置或展示页码当作出处。受限 `contentEditable` 不新增编辑器运行依赖；格式命令由 Chromium 编辑能力执行，插入和撤销历史由应用统一管理。后续替换编辑器时迁移文档版本，不绑定编辑器私有状态。

所有加载、序列化和恢复的 HTML 经过允许列表清理。去除 URL、样式、事件属性、脚本及活动元素；粘贴仅接收纯文本。内部引用标记只允许引用当前文档的已知 anchorId，展示内容始终从来源快照重建，引用原文不能被编辑器隐式改写。书内拖放由当前窗口捕获的选区与书籍身份创建主进程锚点，不信任外部拖入 HTML/来源快照。

引用、快照、出处、汇入的批注文字及去重元数据作为一个编辑事务进入有界历史，支持按钮及 Ctrl/Cmd+Z、重做。普通保存不会替换编辑器 DOM，避免破坏选区与历史。旧的原始 HTML/空笔记在读取时转换为版本 1 包装，不自动发布修订；首次成功编辑保存才迁移。未知版本或损坏记录拒绝读写，不静默变成空笔记。

## 出处与批注汇入

主进程用共享阅读适配器创建来源、核对内容哈希，并用共享锚点解析器提供 exact/fallback/lost。保存时验证同书身份及有界完整结构；独立 `sourceSnapshots` 账本保留同一 anchorId 的原始快照，删除再插入也不能改变已确认的来源。正文移除后，书架目录项及笔记仍可读写，失效引用继续显示原文与可读出处。点击回跳前重新解析，失效时不猜测位置。

T-020 的工程规则：只汇入具有批注文字/annotationId 的条目；单条与全部都追加文末，不覆盖用户文字。全部按章节及原文位置排序；同一 annotationId 已汇入则跳过，包括批注后来编辑的情形，不自动覆盖旧笔记中的副本。撤销汇入同时撤销相应去重标记，重做恢复。若用户需要再次汇入批注的新版本，须另行定义显式更新策略，不隐式刷新快照。

## 保存与布局生命周期

每次打开的笔记拥有独立保存会话。最后一次输入后 1.5 秒触发保存（满足 2 秒内开始），待保存/保存中/已保存/失败分开显示。输入发生在请求途中时，串行合并后续输入，使用确认的新修订继续保存；只有当前版本确认后才显示已保存。切书/返回书架/关闭保留笔记面板前等待 flush，失败则保留原编辑器。

写入失败可能发生在原子发布之后，不能盲目重试：先读取最新修订，若与上次发送内容相同则接受已经提交的版本；若修订未变则可重试；若其他新版本不同则阻止覆盖，保留输入并提示导出核对。初次读取失败时禁用编辑，不能用空白内容覆盖未知原记录。异常终止不保证未确认输入；已确认内容遵循 DurableStore 原子修订与校验契约。

恢复导出使用主进程文件对话框，把当前内存中的完整版本化 JSON 写入新文件；包含尚未保存的输入与来源。排他创建拒绝覆盖已有文件，错误可见；它不是 S06 的通用 Markdown 导出，也不是完整备份/恢复功能。

分栏宽度与收起状态合并保存至 `settings.notesLayout`，不改写阅读偏好。鼠标、键盘调整以及窄窗抽屉保持同一个已挂载编辑器；专注模式和收起仅隐藏，保留待保存输入、历史及光标。布局变化重新按逻辑阅读位置还原，不把像素滚动当作进度。
