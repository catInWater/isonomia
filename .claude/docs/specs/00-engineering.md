# S00 工程跑道

状态：草案。需求：NFR-1～5、NFR-6～24、G4/G5、PRD §2.2/10/11。依赖：[范围决策](README.md)。

## 目标与当前基线

空应用可重复安装、自动检查并构建安装包；为后续功能建立数据、测试和文档边界。已有 Nx 22 React/Webpack + nx-electron 骨架，Linux build/lint/typecheck/解包 package 已验证；这不等于 Windows 安装包、GUI 或 CI 已验收。

## 实施契约

1. 固定包管理器和 lockfile，干净环境通过 `npm ci` 安装；Nx 及插件同主版本。记录 Node/npm、Electron 安全支持与升级计划。依赖审计记录来源、影响范围、处理或有期限的接受理由，禁止用强制升级破坏兼容性。
2. CI 在每次 PR 执行 Nx lint、typecheck、测试、build、格式/规格引用检查；检查失败阻止合并。分支保护属于仓库外配置，需独立验收，不能以 YAML 存在视为已生效。
3. Windows 按 D-01 确定的矩阵生成可安装产物，禁用自动发布；安装、启动、退出、卸载和数据保留行为有冒烟记录。Windows 代码签名与下载警告的发布限制明确记录，密钥不入库。
4. 固定合法的 EPUB/TXT 样例：中文、UTF-8/GBK、目录缺失、损坏文件、锚点重复片段、排版变化、长书。记录许可、来源、校验和与用途，不将个人/受限书籍作为测试资源。
5. ADR 覆盖进程/IPC 边界、本地存储与文件所有权、阅读引擎、锚点、编辑器、索引和转换选型；决定前以小型验证回答可行性，避免先写死库。
6. 持久化设计统一规定：原子变更、错误反馈、schema 版本、迁移前快照、失败回滚与恢复。书文件和用户内容分离。恢复至少有明确的备份选择与校验流程，手动完整备份产品功能不在本期。
7. Electron 主进程拥有文件/存储能力；渲染器只使用窄接口。对 IPC 入参、文件路径、书籍内容进行校验；导入内容不执行脚本、不隐式访问网络或任意本机路径。
8. 性能验收记录 OS、CPU、内存、磁盘、构建模式、样例和重复次数。冷启动从进程启动到书架可操作，打开书到正文可读；使用生产构建。先确定代表性基线和统计方式，再判断 5 秒/3 秒阈值。

## 验收

- S00-A1：全新环境遵循 README，10 分钟内运行空应用；列明网络下载与系统前置条件。
- S00-A2：故意引入类型错误/失败测试，CI 红灯且配置的合并检查阻止合并；正常版本全部通过。
- S00-A3：目标系统下载 CI 产物，成功安装启动退出；保留安装包和验证记录。仅 Linux 解包不满足此项。
- S00-A4：已有用户数据迁移前自动留存备份；注入迁移中断与损坏数据，旧数据可恢复且应用展示可操作提示。
- S00-A5：强制终止保存进程后重开，已确认保存的数据完整；输入恢复满足 D-03 最终时限。断网完成除 AI/同步外功能。
- S00-A6：网络监测无遥测、隐式更新检查、第三方追踪和导入内容发起的请求。
- S00-A7：关键模块固定样例测试进入 CI；性能报告覆盖 100 万字、100 本搜索、500 本书架规模。

## 完成证据

CI 运行链接/本地产物记录、安装冒烟结果、样例清单、ADR、数据恢复测试、README 架构概览和真实截图。所有功能票据复用本规格的可靠性与安全契约。
