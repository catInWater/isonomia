# 产品需求文档（PRD）：带着创作去读书的桌面阅读器

版本：0.1　日期：2026-11-18　状态：草案
说明：本文档只描述"做什么、做到什么程度"，不涉及技术选型。技术取舍记录在 `docs/adr/`，各功能的实施规格放在 `docs/specs/`。

---

## 1. 产品概述

### 1.1 一句话定位

一款**本地优先**的桌面阅读器，让读者在阅读的同时随手创作：批注、摘录和笔记都能定位回原文，并且不被任何社交噪音打断。

### 1.2 背景与痛点

作者本人是重度读者，现有工具各有不足：

| 现状 | 痛点 |
|---|---|
| 在浏览器里读电子书 | 想法记在书旁边的地方容易丢失，笔记与原文没有关联 |
| 微信读书 | 他人评论气泡不断打断阅读，浪费时间 |
| 两类工具共同的问题 | 读完之后很难"找回来"：想不起某个概念出现在哪本书哪一页；跨书联想无处安放 |

### 1.3 产品理念

1. **阅读是主角，其他一律克制。** 界面里只出现读者自己的内容。
2. **笔记是创作，不是附属品。** 每本书有一份可连续书写的专属笔记，而不是零散的高亮。
3. **每一句话都能回到原文。** 任何批注和摘录都带有出处锚点。
4. **数据属于读者。** 本机为主，断网可用，随时可导出，不被锁定。
5. **为未来留接口。** v1 存好的出处信息，要足以支撑 v2 的"概念卡片"。

### 1.4 目标用户

**主要用户：作者本人**，一位喜欢文学、哲学类书籍，习惯边读边思考、边读边写的读者。
**次要用户：**与作者类似的深度阅读者，以及项目的评审者（如面试官），他们会在短时间内评估产品的完整度。

### 1.5 平台

- v1：桌面应用，支持 Windows 
- 之后：手机端（只读与摘录）、同步服务，见第 3 节

## 2. 目标与成功标准

### 2.1 产品目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 作者愿意把它当作日常阅读器长期使用 | 连续两周，作者用它完成至少一本书的阅读和笔记 |
| G2 | "读"和"写"同屏，不需要来回切换 | 阅读中记下一条想法不超过 3 次操作，且不离开当前阅读位置 |
| G3 | 任何笔记都能回到原文 | 随机抽查 20 条批注，定位成功率 ≥ 95% |
| G4 | 断网时功能完整 | 断网状态下，除同步和 AI 外所有功能可用 |
| G5 | 数据不丢 | 异常退出、断电后，已输入的笔记最多丢失最近几秒的内容 |

### 2.2 展示目标

项目同时用于展示软件工程能力，因此需满足：

- **2 分钟演示脚本**可完整走通（见第 11 节）
- 全新环境下，按 README 能在 10 分钟内安装并运行
- 每个功能都有对应的规格、测试和提交记录，可被追溯

## 3. 范围

### 3.1 v1（本文档的主体）

书架与导入、阅读、划线与批注、并排笔记、出处锚点、搜索、格式转换与导出、一个小型 AI 辅助功能。

### 3.2 v1.5（v1 稳定后）

多设备同步与备份（见 FR-8）。

### 3.3 v2（远期，不在本期实现）

- **概念卡片与树形知识库**：以"概念"为中心，把不同书中关于同一概念的摘录汇集到一张卡片下，按领域/主题/概念分层管理
- **跨书概念对比**：同名异义、同义异名、同一意象、同一作者前后期演变，并排对照并辅以 AI 提议、人工确认
- 手机端：只读和摘录，长段写作留给桌面端

### 3.4 明确不做

- 任何社交功能：他人评论、热门划线、关注、分享排行
- 书籍商店、购买、内容分发
- 受 DRM 保护书籍的解析
- 在线协作编辑
- v1 不做 PDF 的精排版，不做扫描版 PDF 的文字识别

## 4. 核心概念与术语

| 术语 | 定义 |
|---|---|
| **书** | 读者导入的一份电子书文件及其元数据（书名、作者、封面等） |
| **书架** | 所有书的集合，可按分组或标签组织 |
| **划线** | 读者在正文中选中的一段文字及其高亮标记 |
| **批注** | 附着在某处划线上的一条简短想法 |
| **笔记** | 每本书对应的一份可连续书写的专属文档，可引用划线和批注 |
| **出处锚点** | 描述"这段内容在书中哪里"的信息：书、章节、位置、原文片段（详见 FR-5） |
| **摘录** | 带有出处锚点的原文片段，可被放入笔记 |

## 5. 用户场景

**场景 A：读书时冒出一个想法**
读者读到一个关键概念，选中那句话，直接在旁边写下"这和另一本书里的用法不一样"。写完继续读，视线没有离开正文。
→ 对应 FR-3、FR-4

**场景 B：带着创作读一本书**
读者打开一本书，左边是正文，右边是这本书的笔记。读到好句子就把它拖进笔记，在下面接着写自己的论述。读完时，笔记已经是一篇有引用、有出处的文章雏形。
→ 对应 FR-4、FR-5

**场景 C：想找回之前读过的东西**
读者隐约记得某本书里有一句关于"孤独"的话，但想不起书名。他在全库搜索"孤独"，结果同时列出书中原文和自己写过的笔记，点击即可跳到原处。
→ 对应 FR-6

**场景 D：换一种格式读**
读者有一本 TXT 小说，想以 EPUB 的方式阅读，或想把一本 EPUB 转成 TXT 用于其他工具。
→ 对应 FR-7

**场景 E：整理成文**
读完一本书，读者把这本书的笔记导出为 Markdown，每条引用都附有出处，直接用于写作。
→ 对应 FR-7

## 6. 功能需求

优先级：**P0** 必须有，缺了就不成立；**P1** 应该有，影响体验；**P2** 可以有，时间允许再做。

### FR-1 书架与导入

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-1.1 | 导入 EPUB 文件 | P0 | 选择文件或拖入窗口即可导入，书出现在书架，显示书名、作者和封面 |
| FR-1.2 | 导入 TXT 文件 | P0 | 能自动识别常见中文编码，并尝试按章节标题划分目录；识别失败时仍可整本阅读 |
| FR-1.3 | 批量导入 | P1 | 一次选择多本或整个文件夹，显示进度，单本失败不影响其他 |
| FR-1.4 | 导入失败提示 | P0 | 文件损坏或格式不支持时，给出明确的原因，不崩溃 |
| FR-1.5 | 重复检测 | P1 | 导入同一本书时提示已存在，让读者选择跳过或保留两份 |
| FR-1.6 | 书架浏览 | P0 | 书架以封面或列表展示，可切换；可按书名、作者、最近阅读、导入时间排序 |
| FR-1.7 | 分组与标签 | P1 | 读者可创建分组或打标签，一本书可属于多个标签 |
| FR-1.8 | 删除书籍 | P0 | 删除前需确认，并明确告知该书的笔记和批注是否一并删除；提供"仅移除书文件、保留笔记"的选项 |
| FR-1.9 | 元数据编辑 | P2 | 可修改书名、作者、封面 |
| FR-1.10 | 导入 PDF 并阅读 | P2 | 能打开并翻页阅读；划线与批注能力可降级，需在界面上明确说明 |

### FR-2 阅读

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-2.1 | 正文渲染与翻页 | P0 | 支持分页或滚动两种阅读模式，翻页响应无明显卡顿 |
| FR-2.2 | 目录导航 | P0 | 显示书籍目录，点击跳转到对应章节 |
| FR-2.3 | 阅读进度自动保存 | P0 | 关闭应用后再打开，回到上次阅读位置，误差不超过一页 |
| FR-2.4 | 排版设置 | P0 | 可调字号、行距、页边距、字体；设置即时生效并被记住 |
| FR-2.5 | 主题 | P1 | 至少提供浅色、深色、护眼三种主题 |
| FR-2.6 | 零社交噪音 | P0 | 阅读界面中不出现任何他人的内容或推荐类元素 |
| FR-2.7 | 专注模式 | P1 | 一键隐藏所有界面元素，仅保留正文 |
| FR-2.8 | 阅读统计 | P2 | 记录每本书的阅读时长与进度，仅本人可见 |
| FR-2.9 | 键盘操作 | P1 | 翻页、目录、搜索、新建批注都有快捷键，且可在设置里查看 |

### FR-3 划线与批注

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-3.1 | 划线 | P0 | 选中文字后可一键高亮，支持多种颜色；高亮在重新打开后依然存在 |
| FR-3.2 | 批注 | P0 | 选中文字后可直接输入批注，输入时不离开当前阅读位置，也不遮挡所选文字 |
| FR-3.3 | 删除与修改 | P0 | 可修改批注内容、改颜色、删除划线；删除前有撤销机会 |
| FR-3.4 | 批注与原文双向跳转 | P0 | 点击批注定位到原文并闪现高亮；点击原文上的高亮显示对应批注 |
| FR-3.5 | 书内划线列表 | P1 | 可按章节或时间查看本书所有划线和批注，点击跳转 |
| FR-3.6 | 跨页、跨章选区 | P1 | 选区跨页时划线仍然成立 |
| FR-3.7 | 批注标签 | P2 | 可给批注加标签，用于之后筛选 |

### FR-4 并排笔记

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-4.1 | 每本书一份专属笔记 | P0 | 打开书时自动关联对应笔记，无需手动创建 |
| FR-4.2 | 左读右写的并排布局 | P0 | 正文与笔记同时可见，读者无需翻页或切换标签；分栏比例可拖动调整，也可收起笔记栏 |
| FR-4.3 | 自动保存 | P0 | 输入过程中持续自动保存，不需要手动保存按钮；异常退出后内容不丢 |
| FR-4.4 | 连续书写 | P0 | 笔记是一篇可自由书写的长文，支持标题、列表、引用、加粗等基础排版 |
| FR-4.5 | 引用原文 | P0 | 可把选中的原文一键插入笔记，作为带出处的引用块；点击引用块可回到原文位置 |
| FR-4.6 | 批注汇入笔记 | P1 | 可选择把批注插入笔记，或一键把本书全部批注按章节整理进笔记 |
| FR-4.7 | 笔记大纲 | P2 | 笔记较长时显示标题大纲，便于跳转 |
| FR-4.8 | 窄窗口退化 | P1 | 窗口宽度不足时，笔记栏可作为抽屉拉出，不破坏阅读体验 |

### FR-5 出处锚点

这是整个产品的地基，为 v2 概念卡片和跨书对比预留。

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-5.1 | 完整的锚点信息 | P0 | 每条划线、批注、摘录都保存：书的标识、章节、书内位置、原文片段（含前后少量上下文）、创建时间 |
| FR-5.2 | 稳定定位 | P0 | 改变字号、排版、窗口大小后，锚点仍然指向同一处原文 |
| FR-5.3 | 失效降级 | P0 | 当位置无法精确还原时（如书文件被替换），系统用原文片段进行重新匹配；仍失败则保留片段并明确标注"位置丢失"，不得静默丢弃 |
| FR-5.4 | 可被引用 | P0 | 锚点可以被笔记、导出、搜索结果等其他功能统一使用 |
| FR-5.5 | 出处的可读表示 | P1 | 导出或展示时，出处以"书名 · 作者 · 章节"的人类可读形式呈现 |
| FR-5.6 | 为 v2 预留 | P1 | 每条摘录可记录所属"领域"这一可选字段（v1 不提供界面，仅保留数据位） |

### FR-6 搜索

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-6.1 | 书内搜索 | P0 | 在当前书中搜索，结果列出所在章节和上下文，点击跳转并高亮 |
| FR-6.2 | 全库搜索 | P0 | 在所有书的正文中搜索，结果按书分组，显示片段与出处 |
| FR-6.3 | 搜索自己的内容 | P0 | 能同时搜索批注、笔记，并在结果中与书文正文区分显示 |
| FR-6.4 | 中文检索质量 | P0 | 搜索中文词语能得到合理结果，不要求用户输入完整句子；单字与双字词均可检索 |
| FR-6.5 | 搜索速度 | P0 | 在 100 本书的规模下，输入后 1 秒内出结果 |
| FR-6.6 | 搜索范围过滤 | P1 | 可限定范围：当前书、某个分组、仅批注与笔记 |
| FR-6.7 | 结果高亮与排序 | P1 | 命中词高亮，相关度高的排在前面 |
| FR-6.8 | 导入后自动建立索引 | P0 | 新导入的书在合理时间内可被搜索；索引过程在后台进行，不阻塞阅读 |
| FR-6.9 | 语义搜索 | P2 | 用意思而非字面检索自己的笔记（与 FR-9 共用，可选） |

### FR-7 格式转换与导出

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-7.1 | EPUB 转 TXT | P1 | 保留章节顺序，章节标题清晰可辨；转换在后台进行并显示进度 |
| FR-7.2 | TXT 转 EPUB | P1 | 自动识别章节生成目录，可设置书名、作者和封面；转换结果可被本应用正常打开 |
| FR-7.3 | 转换不影响原书 | P0 | 转换产生新文件，原书与其批注保持不变 |
| FR-7.4 | 转换失败提示 | P0 | 给出具体原因，且不留下损坏的半成品 |
| FR-7.5 | 笔记导出为 Markdown | P0 | 一本书的笔记可导出为单个 Markdown 文件，引用块附带出处 |
| FR-7.6 | 批注导出 | P1 | 可导出一本书的全部划线与批注，按章节排列，含出处 |
| FR-7.7 | 全部数据导出 | P1 | 一次性导出所有笔记和批注，使用通用、可读的格式，读者离开本应用时不被锁定 |
| FR-7.8 | 其他格式互转（如 MOBI） | P2 | 视时间决定 |

### FR-8 同步与备份（v1.5）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-8.1 | 本地备份与恢复 | P1 | 可手动导出完整备份并在另一台电脑恢复，恢复后批注、笔记、进度完整 |
| FR-8.2 | 多设备同步 | P2 | 在两台设备上登录同一账号，笔记、批注、阅读进度保持一致 |
| FR-8.3 | 离线优先 | P2 | 断网时一切功能照常，恢复联网后自动同步，不需要读者介入 |
| FR-8.4 | 冲突处理 | P2 | 同一条内容在两端被修改时，不得丢失任何一方的内容；v1.5 的默认策略为"保留较新者，较旧者留作历史版本" |
| FR-8.5 | 同步范围可选 | P2 | 读者可选择只同步笔记与批注，或连同书籍文件一起同步 |
| FR-8.6 | 同步可关闭 | P1 | 不使用同步时，应用不发起任何网络连接（AI 功能除外，且需读者主动启用） |

### FR-9 小型 AI 辅助

AI 是辅助，不是主角。v1 只做一个小而准的功能，服务于"带着创作去读书"。

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-9.1 | 划线后的"帮我起笔" | P2 | 选中一段原文后，可请求 AI 给出：一句话摘要、2~3 个值得思考的追问。结果仅供参考，由读者决定是否放进笔记 |
| FR-9.2 | 可选且可关闭 | P0（若实现 AI） | 默认关闭，由读者主动开启；关闭或不可用时，其余功能完全不受影响 |
| FR-9.3 | 数据透明 | P0（若实现 AI） | 开启前明确告知：哪些内容会被发送到外部服务；每次请求前读者能看到将发送的文本 |
| FR-9.4 | 来源清晰 | P0（若实现 AI） | AI 生成的内容在笔记中带有明确标记，与读者自己写的内容区分开 |
| FR-9.5 | 失败不阻塞 | P0（若实现 AI） | 网络错误、超时、额度不足时给出提示，读者可以继续阅读和写作 |

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|

| FR-10.2 | 外观与阅读默认值 | P1 | 可设置默认主题、字号、字体 |
| FR-10.3 | 语言 | P2 | 界面语言先支持中文，预留多语言能力 |

## 7. 非功能需求

### 7.1 性能

| 编号 | 需求 |
|---|---|
| NFR-1 | 应用冷启动到可操作不超过 5 秒（在普通办公笔记本上） |
| NFR-2 | 打开一本常规体量的书（约 100 万字）不超过 3 秒 |
| NFR-3 | 翻页、划线、输入批注无肉眼可见的延迟 |
| NFR-4 | 导入和建立索引在后台进行，期间读者可继续使用应用 |
| NFR-5 | 书架规模 500 本以内，界面依然流畅 |

### 7.2 可靠性与数据安全

| 编号 | 需求 |
|---|---|
| NFR-6 | 读者产生的数据（批注、笔记、进度）一旦输入，即使应用崩溃或断电，也不会整体丢失 |

## 8. 界面与交互原则

1. **读者的视线不离开正文。** 记录想法时，输入框出现在选中文字附近或旁边的笔记栏，而不是弹出遮盖正文的窗口。
2. **一眼分清"书的内容"和"我的内容"。** 原文、读者的批注、读者的笔记、AI 生成内容，在视觉上有明确区分。
3. **克制。** 默认界面只有正文和必要的少量控件，其余按需出现。
4. **可撤销。** 读者不应该因为误操作而担心丢失劳动成果。
5. **同一件事只有一种做法。** 避免相似功能出现多个入口造成困惑。
6. **读写比例由读者决定。** 笔记栏可拖宽、可收起，布局会被记住。

## 9. 数据需求（逻辑层面）

读者数据按"可读、可移植"的原则设计：

- **书**：文件本身、元数据、所属分组和标签、阅读进度、最近打开时间
- **划线 / 批注**：所属的书、颜色、批注内容、出处锚点、创建与修改时间
- **笔记**：所属的书、正文内容、其中引用的锚点、创建与修改时间
- **摘录**：原文片段、出处锚点、可选的领域字段（为 v2 预留）
- **设置**：外观与阅读偏好

要求：
- 任何一条读者产生的数据，都能被导出为通用格式
- 书籍文件与读者数据分开存放，读者数据的损坏或迁移不会影响书籍文件
- 数据结构的变更必须可迁移，旧版本数据不被抛弃

## 11. 演示脚本（2 分钟）

1. **（15 秒）** 打开应用，展示书架，导入一本 EPUB，几秒后出现在书架上。
2. **（30 秒）** 打开这本书，展示左读右写的并排布局。选中一句话，直接写下一条批注，视线没有离开正文。
3. **（20 秒）** 把一段原文拖进笔记作为引用，接着写自己的论述；点击引用，跳回原文。
4. **（20 秒）** 调整字号、切换主题，笔记栏拖宽再收起，说明所有设置都被记住。
5. **（20 秒）** 全库搜索一个中文词，结果同时包含书中原文和自己的笔记，点击跳转。
6. **（10 秒）** 把这本书的笔记导出为 Markdown，打开文件，引用带有出处。
7. **（5 秒）** 展示仓库里的流水线：每次提交都被自动检查，并能构建出安装包。

## 12. 风险与假设

| 风险 / 假设 | 影响 | 应对 |
|---|---|---|
| 出处锚点在排版变化后失效 | 笔记无法回到原文，核心价值受损 | 把锚点作为独立阶段重点测试；保留原文片段作为兜底（FR-5.3） |
| 中文检索质量不足 | 搜索体验差，场景 C 无法成立 | 阶段 5 专门评估并选择方案，用真实中文书做验收 |
| TXT 章节识别不准 | 目录混乱 | 提供手动调整章节规则的能力，识别失败时仍可整本阅读 |
| 格式转换质量参差 | 转换后排版丢失 | v1 只承诺 EPUB 与 TXT，不承诺其他格式 |
| AI 功能引入隐私顾虑 | 与"数据属于读者"冲突 | 默认关闭、发送前可见、可完全不用（FR-9） |
| 个人项目时间有限 | 范围膨胀导致做不完 | 严格按优先级推进；P0 完成并稳定后才碰 P1；P2 随时可砍 |
| 同步比预期复杂 | 拖累主线 | 同步放在 v1.5，v1 不依赖它 |
